# ของแมวเหมียว (cat-shop)

หน้าร้านขายของแมว (React) + ระบบสมัคร/เข้าสู่ระบบ (Express + MongoDB)

## โครงสร้าง

- `client/` หน้าเว็บด้วย React + Vite + React Router
  - `src/pages/Shop.jsx` หน้าร้าน, `src/pages/AuthPage.jsx` หน้าเข้าสู่ระบบ/สมัครสมาชิก
  - `src/context/` สถานะผู้ใช้ (`AuthContext`) และตะกร้า (`CartContext`)
  - `src/data/products.js` สินค้าตัวอย่าง
- `server.js` เซิร์ฟเวอร์ Express เชื่อม MongoDB และเสิร์ฟหน้าเว็บที่ build แล้ว
- `models/User.js` โมเดลผู้ใช้, `routes/auth.js` API สมาชิก

## เตรียมเครื่อง

ต้องมี Node.js 18 ขึ้นไป และ MongoDB (ในเครื่อง หรือ MongoDB Atlas)

    npm install
    npm run client:install

คัดลอก `.env.example` เป็น `.env` แล้วใส่ `MONGODB_URI` กับ `JWT_SECRET`

## ตอนพัฒนา (เปิด 2 Terminal)

Terminal 1 รันเซิร์ฟเวอร์ API ที่พอร์ต 3000

    npm run dev

Terminal 2 รันหน้าเว็บ React ที่พอร์ต 5173 (ส่งคำขอ /api ไปหาเซิร์ฟเวอร์ให้เอง)

    npm run client:dev

เปิด http://localhost:5173

## ตอนใช้งานจริง (เซิร์ฟเวอร์เดียว)

    npm run build
    npm start

เปิด http://localhost:3000

## สินค้าและแอดมิน

สินค้าเก็บใน MongoDB (คอลเลกชัน `products`) ดูแลผ่านหน้า `/admin`

1. ใส่สินค้าตัวอย่างครั้งแรก: `npm run seed` (ถ้ามีสินค้าอยู่แล้วจะไม่ทำซ้ำ)
2. สมัครสมาชิกในเว็บด้วยอีเมลของเจ้าของร้านก่อน แล้วตั้งสิทธิ์แอดมินด้วยคำสั่ง

       npm run make-admin -- อีเมลของคุณ@gmail.com

   (ถอนสิทธิ์ด้วยการใส่ `--remove` ท้ายคำสั่ง) แล้วออกจากระบบ/เข้าใหม่หนึ่งครั้ง จะเห็นลิงก์ "จัดการสินค้า" ที่มุมบน
3. หน้า `/admin` เพิ่ม แก้ไข ลบ ซ่อน/แสดงสินค้า แก้จำนวนสต็อก และอัปโหลด/เปลี่ยน/ลบรูปสินค้าได้ (รูปเก็บใน MongoDB คอลเลกชัน `images` หน้าเว็บย่อรูปให้อัตโนมัติ ถ้าไม่มีรูปจะใช้ภาพประกอบ SVG แทน) สินค้าที่สต็อกเป็น 0 จะขึ้น "สินค้าหมด" ในหน้าร้าน

สิทธิ์แอดมินตั้งได้ผ่านคำสั่งในเครื่องเซิร์ฟเวอร์เท่านั้น ไม่มี API ให้ใครขอสิทธิ์ผ่านเว็บ

## ออเดอร์ ที่อยู่ รีวิว และแดชบอร์ด

**ออเดอร์** ลูกค้าต้องเข้าสู่ระบบก่อนสั่งซื้อ เซิร์ฟเวอร์รับเฉพาะรหัสสินค้ากับจำนวน แล้วคิดราคา ค่าส่ง และตัดสต็อกเองทั้งหมด (ค่าตั้งอยู่ที่ `config/shop.js` ยอดส่งฟรี 499 บาท ค่าส่ง 40 บาท) ออเดอร์เก็บสำเนาชื่อและราคาสินค้า ณ ตอนสั่ง
สถานะ: รอชำระเงิน → ชำระเงินแล้ว → จัดส่งแล้ว (ใส่เลขพัสดุได้) หรือ ยกเลิก (คืนสต็อกให้อัตโนมัติ) แอดมินเปลี่ยนสถานะที่ `/admin/orders` ลูกค้ายกเลิกเองได้เฉพาะออเดอร์ที่ยังรอชำระเงิน
ตอนนี้ **ยังไม่เชื่อมระบบชำระเงิน** แอดมินต้องกด "ยืนยันว่าชำระเงินแล้ว" เองหลังเช็กว่าเงินเข้า

**ตะกร้า** เก็บในเบราว์เซอร์แยกตามบัญชี (ใครล็อกอินก็เห็นเฉพาะตะกร้าของตัวเอง) ส่วนคนที่ยังไม่ล็อกอินมีตะกร้าชั่วคราวของตัวเอง พอล็อกอินระบบจะรวมของที่หยิบไว้เข้าตะกร้าของบัญชีนั้น ออกจากระบบแล้วตะกร้าของบัญชียังอยู่ รอวันกลับมาล็อกอิน ตะกร้าเดิมที่ทุกบัญชีเคยใช้ร่วมกัน (เวอร์ชันเก่า) จะถูกลบทิ้งหนึ่งครั้ง ไม่ปล่อยให้ตกไปอยู่กับบัญชีใด ตะกร้าอยู่ในเบราว์เซอร์เครื่องนั้น ไม่ได้ซิงก์ข้ามเครื่อง

**ที่อยู่จัดส่ง** บันทึกได้สูงสุด 10 รายการต่อบัญชี ตั้งที่อยู่หลักได้ จัดการที่ `/account` หรือติ๊ก "บันทึกที่อยู่นี้" ตอนสั่งซื้อ

**รีวิวและคะแนน** กดชื่อหรือรูปสินค้าในหน้าร้านเพื่อดูรายละเอียดและรีวิว รีวิวได้หลังลูกค้ากด "ยืนยันรับสินค้า" ที่หน้า "บัญชีของฉัน" (ออเดอร์ต้องเป็น "จัดส่งแล้ว" ก่อน แล้วเปลี่ยนเป็น "ได้รับสินค้าแล้ว") และเขียนรีวิวใต้สินค้าแต่ละรายการในหน้าคำสั่งซื้อนั้นเลย (หนึ่งคนต่อหนึ่งสินค้า แก้ไขภายหลังได้) ชื่อผู้รีวิวแสดงแบบปิดบังบางส่วน เจ้าของลบรีวิวตัวเองได้ แอดมินลบรีวิวใดก็ได้

**เกี่ยวกับเรา / ติดต่อเรา** ลิงก์อยู่ท้ายทุกหน้า (`/about`, `/contact`) แอดมินแก้ข้อมูลติดต่อ (เบอร์โทร LINE อีเมล Facebook ที่อยู่ เวลาทำการ) ได้ที่เมนู "ตั้งค่าร้าน" ในหน้าจัดการร้าน (`/admin/settings`) ช่องที่เว้นว่างจะไม่แสดง ส่วนเรื่องราวของร้านแก้ที่ไฟล์ `client/src/data/shopInfo.js` ฟอร์ม "ส่งข้อความถึงร้าน" ส่งอีเมลไปที่ `CONTACT_EMAIL` ใน `.env` (ถ้าไม่ตั้งใช้อีเมลร้านจาก "ตั้งค่าร้าน") (ยังไม่ตั้ง SMTP ข้อความจะแสดงใน terminal) แก้ไฟล์ `shopInfo.js` แล้วต้อง build หน้าเว็บใหม่

**เมนูด้านบน** มีสามเมนูย่อย: "สินค้า" (ลิงก์เข้าแต่ละหมวด เช่น `/?cat=food`), "ช่วยเหลือ" (วิธีสั่งซื้อ การจัดส่งและค่าส่ง การชำระเงิน การคืนสินค้า นโยบายความเป็นส่วนตัว ที่ `/help/...`) และ "เกี่ยวกับเรา" เนื้อหาหน้าช่วยเหลือเขียนจากวิธีที่ระบบทำงานจริง (ค่าส่งดึงจากเซิร์ฟเวอร์) แก้ข้อความได้ที่ `client/src/data/helpPages.js` แล้ว build ใหม่ หน้าการคืนสินค้าไม่ได้กำหนดจำนวนวันหรือเงื่อนไขเฉพาะ เจ้าของร้านควรเพิ่มนโยบายของตัวเองและตรวจนโยบายความเป็นส่วนตัวให้ตรงกับการใช้งานจริง

**แจ้งคืน/เปลี่ยนสินค้า** ออเดอร์ที่ลูกค้ากด "ยืนยันรับสินค้า" แล้วจะมีปุ่ม "แจ้งคืน/เปลี่ยนสินค้า" ในหน้า "บัญชีของฉัน" (แจ้งได้ภายใน 7 วันหลังรับสินค้า ปรับได้ด้วย `RETURN_WINDOW_DAYS` ใน `.env`) ลูกค้าเลือกสินค้าและจำนวน เหตุผล และแนบรูปหลักฐาน 1-4 รูป (ย่อรูปในเบราว์เซอร์ก่อนส่ง เก็บใน MongoDB และเปิดดูได้เฉพาะเจ้าของกับแอดมิน) แอดมินตรวจที่แท็บ "คำขอคืนสินค้า" (มีตัวเลขคำขอที่รอตรวจ) อนุมัติโดยเลือกวิธีดำเนินการ (คืนเงิน/ส่งของใหม่/อื่น ๆ) หรือไม่อนุมัติพร้อมเหตุผล แล้วกด "ดำเนินการเสร็จแล้ว" เมื่อร้านคืนเงินหรือส่งของใหม่เรียบร้อย ระบบไม่คืนเงินและไม่คืนสต็อกอัตโนมัติ รูปที่อัปโหลดแล้วไม่ได้ส่งคำขอจะถูกลบเองหลัง 1 วัน

**หลายรูปต่อสินค้า** หน้าแอดมิน "สินค้า" ใส่รูปได้สูงสุด 6 รูปต่อสินค้า (เลือกหลายไฟล์พร้อมกันได้) รูปแรกคือรูปหลักที่แสดงบนการ์ด กด "ตั้งเป็นรูปหลัก" เพื่อสลับ หรือ "ลบ" เพื่อเอาออก ในหน้ารายละเอียดสินค้าลูกค้าเลื่อนดูด้วยปุ่มลูกศรหรือกดรูปเล็กด้านล่าง การ์ดสินค้าที่มีหลายรูปจะมีป้ายบอกจำนวนรูป รูปเก่าที่ถูกถอดออกจะถูกลบจากฐานข้อมูลเมื่อกดบันทึก

**รายการโปรด** ลูกค้ากดรูปหัวใจที่การ์ดสินค้าหรือในหน้ารายละเอียดเพื่อเก็บเป็นรายการโปรด (ถ้ายังไม่ล็อกอินจะพาไปหน้าเข้าสู่ระบบ) ดูรายการทั้งหมดที่ลิงก์ "รายการโปรด" บนแถบด้านบน (`/wishlist`) เก็บที่เซิร์ฟเวอร์แยกตามบัญชี ไม่ปนกันเมื่อสลับผู้ใช้ เก็บได้สูงสุด 200 รายการต่อบัญชี สินค้าที่ถูกลบหรือซ่อนจะไม่แสดงในรายการ

**หน้าตาเว็บ (ธีม aurora)** ส่วนหัวหน้าร้านเป็นพื้นมืดไล่สีเบลอเคลื่อนไหวช้า ๆ (ปิดอัตโนมัติถ้าเครื่องตั้งลดการเคลื่อนไหว) แถบเมนูกระจกฝ้า ปุ่มไล่สีส้ม-ชมพู การ์ดจุดเด่นซ้อนขอบส่วนหัว และการ์ดสินค้าที่ลอยขึ้นเมื่อชี้ ตัวเลขในการ์ดจุดเด่น (ส่งฟรีเมื่อซื้อครบ จำนวนวันแจ้งคืน) ดึงจากค่าจริงของเซิร์ฟเวอร์ สีและเอฟเฟกต์ทั้งหมดอยู่ท้ายไฟล์ `client/src/styles.css` (บล็อก "ธีมใหม่ aurora") แก้สีหลักได้ที่ตัวแปร `--grad`

**ชำระเงิน PromptPay + แนบสลิป** แอดมินใส่เลข PromptPay (เบอร์โทร 10 หลัก / เลขบัตร-ภาษี 13 หลัก / e-Wallet 15 หลัก) และชื่อบัญชีที่ "ตั้งค่าร้าน" ลูกค้าเห็น QR พร้อมยอดเงินหลังสั่งซื้อและในหน้า "บัญชีของฉัน" (QR สร้างในเบราว์เซอร์ตามมาตรฐาน Thai QR Payment ใช้สแกนด้วยแอปธนาคารได้จริง ไม่ต้องใช้บริการภายนอก) แล้วแนบสลิป (เก็บเป็นรูปส่วนตัว เปิดดูได้เฉพาะเจ้าของออเดอร์กับแอดมิน) แอดมินเปิดดูสลิปในหน้าออเดอร์ แล้วกด "ยืนยันว่าชำระเงินแล้ว" หรือ "สลิปไม่ถูกต้อง" (ใส่เหตุผลให้ลูกค้าแนบใหม่) ระบบ **ไม่ได้ตรวจสลิปกับธนาคารอัตโนมัติ** แอดมินต้องเทียบยอด/ชื่อ/เวลากับแอปธนาคารเอง (ถ้าจะตรวจอัตโนมัติ ต้องใช้บริการตรวจสลิปของธนาคารหรือผู้ให้บริการ เช่น SlipOK/EasySlip ซึ่งต้องมีบัญชีจริง) สลิปของออเดอร์ที่ยกเลิกจะถูกลบ ต้องรัน `npm install` ใน `client/` เพราะเพิ่มแพ็กเกจ `qrcode`

**นับถอยหลังชำระเงิน 5 นาที** ออเดอร์ใหม่ต้องแนบสลิปภายใน 5 นาที (ปรับด้วย `PAY_WINDOW_MINUTES` ใน `.env`) หน้า QR มีตัวนับถอยหลัง (คิดจากเวลาที่เซิร์ฟเวอร์ ไม่พึ่งนาฬิกาเครื่องลูกค้า) ครบเวลาแล้วระบบยกเลิกออเดอร์ที่ยังไม่แนบสลิปและคืนสต็อกให้ทันที ทั้งจากตัวตรวจทุก 20 วินาทีและตอนที่หน้าเว็บดึงรายการออเดอร์ แนบสลิปแล้วหยุดนับ (รอแอดมินตรวจ) ถ้าแอดมินกด "สลิปไม่ถูกต้อง" จะเริ่มนับ 5 นาทีใหม่ ออเดอร์เก่าที่สร้างก่อนมีระบบนี้และออเดอร์ที่แอดมินย้อนกลับเป็นรอชำระเงิน จะไม่ถูกยกเลิกอัตโนมัติ

**รีวิวแนบรูป** เขียนรีวิวแนบรูปได้ไม่เกิน 3 รูป (ทั้งจากหน้าคำสั่งซื้อและหน้าต่างสินค้า) รูปย่อในเบราว์เซอร์ก่อนอัปโหลด เก็บในคอลเลกชัน Image แบบ kind='review' แสดงเป็นรูปเล็กใต้รีวิวและกดดูขนาดใหญ่ได้ รูปที่เอาออกจากรีวิว/รีวิวที่ถูกลบ จะลบรูปตามไปด้วย และมีระบบกวาดรูปที่อัปโหลดแล้วไม่ได้ใช้เกิน 1 วันทิ้งอัตโนมัติ

**ธีมมินิมอล** หน้าเว็บเริ่มต้นเป็นธีมมินิมอล (พื้นขาว เส้นบาง ปุ่มสีดำ) สลับกลับเป็นธีม aurora เดิมได้ด้วยปุ่ม "ธีม: ... (สลับ)" ที่ท้ายหน้า ระบบจำค่าไว้ในเบราว์เซอร์ ถ้าชอบธีมไหนแล้ว ลบสไตล์ของอีกธีมออกจาก `styles.css` ได้

**โปรไฟล์และสั่งซ้ำ** หน้า "บัญชีของฉัน" มีแผง "โปรไฟล์ของฉัน" ตั้งรูปโปรไฟล์ (ตัดเป็นจัตุรัส 256px ในเบราว์เซอร์ก่อนอัปโหลด เก็บในคอลเลกชัน Image แบบ kind='avatar' เปลี่ยนรูปแล้วรูปเก่าถูกลบ) ชื่อเล่น (แสดงแทนชื่อจริงบนแถบด้านบน) และแก้ชื่อได้ ถ้าไม่มีรูปแสดงตัวอักษรแรกของชื่อ (บัญชี Google ใช้รูป Google เป็นค่าเริ่มต้น) ทุกออเดอร์มีปุ่ม "สั่งซ้ำ" ใส่สินค้าทั้งชุดลงตะกร้า ข้ามของที่เลิกขาย/หมด และลดจำนวนตามสต็อกที่เหลือ (API: `PUT /api/profile`, `POST/DELETE /api/profile/avatar`)

**ลืมรหัสผ่านบนเว็บ (ไม่ต้องใช้อีเมล)** ตอนสมัครต้องเลือกคำถามความปลอดภัยพร้อมคำตอบ (เก็บคำตอบเป็นแฮช) ตอนลืมรหัสผ่านให้กรอกอีเมล → ตอบคำถาม → ตั้งรหัสใหม่ได้ทันทีและล็อกอินให้เลย ตอบผิดครบ 5 ครั้งบัญชีนั้นถูกล็อก 30 นาที อีเมลที่ไม่มีบัญชีจะได้คำถามปลอมที่ตอบไม่ผ่าน (ไม่บอกว่ามีบัญชีหรือไม่) ผู้ใช้เก่าและบัญชี Google ไปตั้งคำถามได้ที่หน้า "บัญชีของฉัน" บัญชีแอดมินกู้ด้วยวิธีนี้ไม่ได้ (ใช้ลิงก์อีเมลหรือ `npm run make-admin`) ในหน้าลืมรหัสผ่านยังมีตัวเลือกขอลิงก์ทางอีเมลแทน

**ลืมรหัสผ่าน** หน้าเข้าสู่ระบบมีลิงก์ "ลืมรหัสผ่าน?" กรอกอีเมลแล้วระบบส่งลิงก์ตั้งรหัสผ่านใหม่ (ใช้ได้ 60 นาที ใช้ได้ครั้งเดียว เก็บในฐานข้อมูลเป็นแฮชเท่านั้น) ระบบตอบข้อความเดียวกันไม่ว่ามีอีเมลนั้นหรือไม่ ถ้ายังไม่ตั้งค่า SMTP ใน `.env` ลิงก์จะถูกพิมพ์ใน terminal ที่รันเซิร์ฟเวอร์ (ใช้ทดสอบบนเครื่องตัวเองได้) ถ้าจะส่งอีเมลจริงให้ตั้ง `SMTP_*`, `MAIL_FROM` และ `APP_URL` (ดู `.env.example`) แล้วรัน `npm install` เพราะเพิ่มแพ็กเกจ nodemailer

**ยืนยันรับสินค้าอัตโนมัติ** ออเดอร์ที่ "จัดส่งแล้ว" เกิน 7 วัน (ปรับได้ด้วย `AUTO_RECEIVE_DAYS` ใน `.env`) แล้วลูกค้ายังไม่กดยืนยัน ระบบจะเปลี่ยนเป็น "ได้รับสินค้าแล้ว" ให้เอง (ตรวจตอนเปิดเซิร์ฟเวอร์และทุกชั่วโมง) ลูกค้าจึงรีวิวได้ต่อ หน้าบัญชีและหน้าแอดมินจะแสดงวันที่ที่ระบบจะยืนยัน และบอกว่าออเดอร์ไหนถูกยืนยันโดยระบบ

**แดชบอร์ดแอดมิน** (`/admin`) ยอดขายวันนี้ ยอดขายย้อนหลัง 7/30/90 วัน กราฟรายวัน เฉลี่ยต่อออเดอร์ สินค้าขายดี 5 อันดับ สินค้าใกล้หมดสต็อก (เหลือไม่เกิน 5 ชิ้น) และจำนวนออเดอร์รอชำระเงิน ยอดขายนับเฉพาะออเดอร์ที่ชำระเงินแล้วหรือจัดส่งแล้ว ตามวันที่สั่งซื้อ เวลาไทย

## API

| เส้นทาง | หน้าที่ |
|---|---|
| `POST /api/auth/register` | สมัคร ส่ง `{name, email, password}` (รหัสผ่านอย่างน้อย 8 ตัว) |
| `POST /api/auth/login` | ล็อกอิน ส่ง `{email, password}` |
| `POST /api/auth/logout` | ออกจากระบบ |
| `GET /api/auth/me` | คืน `{user}` หรือ `{user: null}` |
| `GET /api/products` | รายการสินค้าที่แสดงอยู่ (สาธารณะ) |
| `GET/POST /api/admin/products`, `PUT/DELETE /api/admin/products/:id` | จัดการสินค้า (แอดมินเท่านั้น) |
| `POST /api/orders` | สั่งซื้อ ส่ง `{items:[{productId, qty}], addressId หรือ address:{name,tel,line}, saveAddress}` (ต้องล็อกอิน) |
| `GET /api/orders`, `POST /api/orders/:id/cancel`, `POST /api/orders/:id/receive` | ประวัติคำสั่งซื้อของฉัน / ยกเลิกออเดอร์ที่ยังรอชำระเงิน / ยืนยันรับสินค้า (ได้เมื่อจัดส่งแล้ว) |
| `GET/POST /api/addresses`, `PUT/DELETE /api/addresses/:id`, `POST /api/addresses/:id/default` | ที่อยู่จัดส่งที่บันทึกไว้ |
| `POST /api/returns`, `GET /api/returns/mine`, `POST /api/returns/:id/withdraw`, `POST /api/returns/images` | แจ้งคืนสินค้า / คำขอของฉัน / ยกเลิกคำขอ / อัปโหลดรูปหลักฐาน |
| `GET/PATCH /api/admin/returns` | แอดมินตรวจคำขอคืนสินค้า |
| `GET /api/wishlist`, `PUT/DELETE /api/wishlist/:productId` | รายการโปรดของฉัน (ต้องล็อกอิน) |
| `GET /api/auth/questions`, `PUT /api/auth/security-question`, `POST /api/auth/security-question`, `POST /api/auth/reset-by-answer` | รายการคำถาม / ตั้งคำถามของตัวเอง / ขอดูคำถามของอีเมล / ตอบคำถามแล้วตั้งรหัสใหม่ |
| `POST /api/auth/forgot`, `POST /api/auth/reset` | ขอลิงก์รีเซ็ตรหัสผ่าน / ตั้งรหัสผ่านใหม่จาก token |
| `GET/POST /api/products/:id/reviews`, `DELETE /api/reviews/:id`, `GET /api/reviews/mine` | รีวิวสินค้า (ดูได้ทุกคน เขียนได้เมื่อยืนยันรับสินค้าแล้ว) / รีวิวของฉัน |
| `GET /api/admin/orders`, `PATCH /api/admin/orders/:id` | จัดการออเดอร์ `{status, tracking}` (แอดมิน) |
| `GET /api/admin/stats?days=30` | ข้อมูลแดชบอร์ด (แอดมิน) |
| `GET /api/images/:id` | แสดงรูปสินค้า (สาธารณะ) |
| `POST /api/admin/images` | อัปโหลดรูป (ส่งไฟล์ JPG/PNG/WebP ตรง ๆ ไม่เกิน 1 MB) แอดมินเท่านั้น |
| `GET /api/auth/config` | บอกหน้าเว็บว่ามี Google Client ID ไหม |
| `POST /api/auth/google` | ล็อกอินด้วย Google ส่ง `{credential}` |

## เข้าสู่ระบบด้วย Google (ไม่บังคับ)

1. สร้าง OAuth Client ID ชนิด Web application ที่ Google Cloud Console (APIs & Services > Credentials)
2. ใส่ Authorized JavaScript origins: `http://localhost:5173` และ `http://localhost:3000` (ตอนขึ้นเว็บจริงเพิ่มโดเมนจริงด้วย)
3. คัดลอก Client ID (ลงท้าย `.apps.googleusercontent.com`) ไปใส่ `GOOGLE_CLIENT_ID=` ใน `.env` แล้วรีสตาร์ตเซิร์ฟเวอร์
4. ถ้าไม่ใส่ ปุ่ม Google จะไม่แสดงและระบบอีเมล/รหัสผ่านยังใช้ได้ปกติ

เซิร์ฟเวอร์ตรวจ ID token กับ Google เอง (`POST /api/auth/google`) ถ้าอีเมล Google ตรงกับบัญชีที่เคยสมัครด้วยรหัสผ่าน ระบบจะผูกบัญชีเข้าด้วยกันและลบรหัสผ่านเดิมออก

## ความปลอดภัยที่ทำไว้แล้ว

- เก็บเฉพาะรหัสผ่านที่แฮชด้วย bcrypt (cost 12)
- เซสชันเป็น JWT ใน cookie แบบ httpOnly, SameSite=Lax (เปิด `secure` เมื่อ `NODE_ENV=production` ต้องรันหลัง HTTPS)
- จำกัดความถี่การสมัคร/ล็อกอินต่อ IP
- ข้อความตอนล็อกอินผิดไม่บอกว่าอีเมลมีในระบบหรือไม่

## ยังไม่ได้ทำ

ลืมรหัสผ่าน, ยืนยันอีเมล, ระบบชำระเงินอัตโนมัติ (PromptPay/บัตร), อีเมลแจ้งเตือนออเดอร์, หลายรูปต่อสินค้า, คำนวณค่าส่งตามน้ำหนัก/จังหวัด, ล็อกอินด้วย LINE

## ขึ้นออนไลน์ (Deploy): หน้าเว็บบน Vercel + API บน Render

โครงสร้าง: หน้าเว็บ (React) อยู่ Vercel, `/api/*` ถูก Vercel ส่งต่อ (rewrite ใน `client/vercel.json`) ไปที่เซิร์ฟเวอร์ Express บน Render ฐานข้อมูลอยู่ MongoDB Atlas เบราว์เซอร์เห็นเป็นโดเมนเดียว (Vercel) จึงไม่ต้องตั้ง CORS และคุกกี้ล็อกอินใช้ได้ปกติ

1. Atlas: สร้างผู้ใช้/ฐานข้อมูลใหม่สำหรับออนไลน์ และเพิ่ม `0.0.0.0/0` ที่ Network Access
2. Render (API): Build Command `npm install`, Start Command `npm start`, Health Check `/healthz` ตั้ง Environment Variables: `NODE_ENV=production`, `MONGODB_URI`, `JWT_SECRET` (สุ่มใหม่), `TRUST_PROXY=2`, `APP_URL` (ที่อยู่เว็บบน Vercel)
3. แก้ `client/vercel.json` ใส่ที่อยู่ Render จริงแทน `YOUR-RENDER-APP.onrender.com`
4. Vercel (หน้าเว็บ): Root Directory = `client` (Framework Vite, Build `npm run build`, Output `dist`)
5. ฐานข้อมูลใหม่: รัน `npm run seed` และ `npm run make-admin` จากเครื่องตัวเองโดยตั้ง `MONGODB_URI` ชี้ฐานข้อมูลออนไลน์
6. Google ล็อกอิน: เพิ่มที่อยู่เว็บบน Vercel ใน Authorized JavaScript origins

ข้อควรรู้: Render ฟรีหลับเมื่อไม่มีคนเข้า ~15 นาที (คำขอแรกหลังหลับช้า 30-60 วินาที) และบล็อกพอร์ตส่งอีเมล (SMTP) ลิงก์รีเซ็ตรหัสผ่านทางอีเมลและข้อความหน้าติดต่อจึงไม่ถึง (ใช้การกู้รหัสผ่านด้วยคำถามความปลอดภัยแทน) Vercel แพ็กเกจ Hobby ไว้ใช้ส่วนตัว/ไม่เชิงพาณิชย์ ถ้าจะขายจริงควรดูเงื่อนไขของแพ็กเกจ
